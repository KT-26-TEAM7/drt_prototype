# Mi:dm 2.0 vs Gemini API 비교 테스트 결과

- 테스트 도구: `compare_models.py`
- 테스트 환경: 로컬 macOS (Apple Silicon), Mi:dm은 로컬 추론 / Gemini는 `gemini-flash-latest` API
- 시나리오: 짧은 대답 → 무릎 통증 호소 → 외로움 호소 → 통화 종료 유도 (동일한 `prompts/system_prompt.txt` 사용)

## 대화 결과

| # | 어르신 발화 | Mi:dm (로컬) | Gemini API |
|---|---|---|---|
| 1 | 그냥 그렇지 뭐. | 그러셨어요. 혹시 식사는 잘 챙겨 드세요? *(8.68초)* | 그러셨어요. 오늘 식사는 잘 챙겨 드셨어요? *(4.15초)* |
| 2 | 요즘 무릎이 아파서 잠을 잘 못 자. | 아이고, 무릎이 아프셔서 잠까지 설치셨구나. 많이 힘드시겠어요.**法** *(5.24초)* | 아이고, 무릎이 아프셔서 잠까지 잘 못 주무셨다니 많이 힘드시겠어요. 병원에는 한번 다녀오셨어요? *(3.74초)* |
| 3 | 자식들이 통 연락이 없어서 적적해. | 많이 적적하셨겠어요. 어르신 마음이 어떠셨을지 짐작이 가요. *(18.0초)* | 자식분들 연락을 기다리시느라 마음이 참 허전하고 적적하셨겠어요. 그럴 때는 보통 어떻게 시간을 보내세요? *(4.82초)* |
| 4 | 이제 그만 끊을게. | 네, 어르신. 드라마 재미있게 보세요. 또 전화드릴게요. *(7.12초)* | 네, 어르신. 오늘 이야기 나눠서 참 좋았어요. 편안히 쉬시고 또 전화드릴게요. *(2.9초)* |

**평균 응답시간 — Mi:dm: 9.76초 / Gemini: 3.90초**

## 관찰 포인트별 정리

### 1) 단어 범주 / 말투 규칙 준수
- 존댓말, 문장 길이(1~2문장), 진단·처방 회피 등 기본 규칙은 **둘 다 잘 지킴**.
- 다만 Mi:dm 2번 응답 끝에 한자 **`法`이 한 글자 섞여 나옴** — system_prompt.txt가 명시적으로 금지한 규칙(한자 사용 금지) 위반. 음성(TTS)으로 읽힐 때 오작동 가능성이 있어 주의 필요.
- `compare_models.py`의 자동 위반 감지에 원래 한자 체크가 빠져있어서 이번에 놓칠 뻔함 → 스크립트에 한자 탐지 로직 추가해둠. 향후 재실행 시 자동으로 잡힘.

### 2) 맥락에 따른 추가 정보 요청 (문맥 파악)
- **Gemini가 확실히 더 적극적으로 되물음.**
  - 2번 턴: 무릎 통증 호소에 Gemini는 "병원에는 한번 다녀오셨어요?"까지 자연스럽게 이어 물음. Mi:dm은 공감만 하고 질문 없이 끝남.
  - 3번 턴: 외로움 호소에 Gemini는 "그럴 때는 보통 어떻게 시간을 보내세요?"로 대화를 이어갈 후속 질문을 생성. Mi:dm은 system_prompt.txt의 few-shot 예시 문장("많이 적적하셨겠어요. 어르신 마음이 어떠셨을지 짐작이 가요.")을 **거의 그대로 재현**함.
  - 즉 Mi:dm(2B, Mini 모델)은 few-shot 예시에 그대로 의존하는 경향이 있어, 예시에 없는 상황에서 일반화가 약할 가능성이 있음. 실제 서비스에서는 대화 패턴이 훨씬 다양할 텐데 더 많은 few-shot을 넣거나 파인튜닝이 필요할 수 있음.

### 3) 응답 딜레이
- Gemini가 **약 2.5배 빠름** (평균 3.90초 vs 9.76초, 로컬 CPU/MPS 기준).
- Mi:dm은 응답 길이·문맥에 따라 편차가 큼 (5초~18초). 특히 3번 턴에서 18초까지 걸림 — 실제 통화 서비스라면 체감 대기시간이 부담될 수 있음.
- 다만 이 비교는 GPU 서버가 아닌 로컬 Mac 기준이라, Mi:dm을 실제 GPU 서버에 올리면 격차가 줄어들 가능성은 있음. (참고용 수치)

### 4) 통화 종료 마커(`[통화종료]`) 처리
- 이번 실행에서는 두 모델 다 정상적으로 마커를 붙임(내부적으로 감지되어 화면엔 안 보임, `end_call_marker: true`).
- 단, 이전에 Gemini만 따로 테스트했을 때는 같은 문장("이제 그만 끊을게")에서 마커를 빠뜨린 적이 있었음 — **Gemini는 마커 지시를 지키는 게 Mi:dm보다 덜 안정적**일 수 있음. 여러 번 반복 테스트해서 재현율을 확인해볼 필요가 있음.

## 정리 및 제안
- **속도**: Gemini 우세 (로컬 환경 기준 2.5배 이상 빠름)
- **맥락 대응**: Gemini 우세 (후속 질문을 더 자연스럽게 생성, few-shot에 덜 의존)
- **규칙 준수 안정성**: 우열 애매 — Mi:dm은 한자 유출 1건, Gemini는 종료 마커 누락 가능성 있음. 둘 다 여러 번 반복 테스트로 재현율 확인 필요
- API 방식(Gemini)이 속도·맥락 면에서 낫다는 최초 가설과 방향은 맞는 것으로 보이나, **종료 마커 안정성**은 별도로 검증하고 필요하면 Gemini용 프롬프트를 좀 더 명시적으로 다듬는 게 좋을 것 같음

## 재현 방법

